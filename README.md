# Bot / Spam Comment Detector

A Python console project for classifying English and Arabic comments using **TF-IDF with a linear SVM**, **TF-IDF with Multinomial Naive Bayes**, and a **bidirectional LSTM**. It supports separate English and Arabic pipelines and a combined multilingual pipeline.

Use the saved-model mode to classify comments without retraining. The training mode collects data, preprocesses text, trains all three classifiers, prints evaluation reports, and saves the resulting pipeline.

## Quick start on Windows

The reference environment is **Windows with Python 3.11.9**, captured from the existing project environment. Start with Python 3.11 to reproduce that setup. Other operating systems and Python versions have not been verified with the saved artifacts.

Open PowerShell in the project folder, or replace the example path below with your own:

```powershell
Set-Location 'C:\path\to\bot-comment-detector'
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m nltk.downloader punkt_tab stopwords
.\.venv\Scripts\python.exe verify_setup.py
.\.venv\Scripts\python.exe main.py
```

These commands create a local environment, install dependencies, download the required NLTK data, check the setup, and open the console. Calling the environment's Python directly means activation is unnecessary.

`requirements.txt` pins the main dependencies and uses `environment-windows.txt` as constraints for dependencies installed alongside them. The snapshot records the existing environment; it is not a validated lockfile and does not require installing its unrelated notebook and debugging tools.

Download NLTK resources once before running the application. The selected NLTK tokenizer requires `punkt_tab`; installing `punkt` alone is insufficient. The application uses the local resources on subsequent runs. See the [NLTK tokenizer implementation](https://www.nltk.org/_modules/nltk/tokenize/punkt.html#PunktTokenizer.load_lang).

### Classify a comment

At the console prompts:

1. Choose **`2`** to load a trained pipeline.
2. Choose **`en`**, **`ar`**, or **`multi`**.
3. Choose **`svm`**, **`nb`**, or **`lstm`**. Pressing Enter selects SVM.
4. Enter a comment to classify. An empty comment returns to the main menu; `q` at the main menu exits.

The program prints a binary label and its numeric value. The LSTM also prints its positive-class probability, using a threshold of `0.5`. SVM and Naive Bayes predictions do not display a probability.

**Label interpretation:** the console retains the original labels `bot` for class `1` and `human` for class `0`. Training combines spam/non-spam and automated-content annotations. These project labels describe the learned classes; a prediction does not establish who authored a comment or whether an AI wrote it.

## Required files

Keep the following paths relative to `main.py`:

| Path | Purpose |
| --- | --- |
| `main.py` | Preprocessing, training, saved-model loading, and interactive console |
| `requirements.txt` | Main dependency pins and reference-environment constraints |
| `environment-windows.txt` | Package versions captured from the existing Windows environment |
| `requirements-training.txt` | Additional packages for rebuilding the training data |

| `saved_models/en/` | English pipeline artifacts |
| `saved_models/ar/` | Arabic pipeline artifacts |
| `saved_models/multi/` | Combined English/Arabic pipeline artifacts |
| `datasets/english/`, `datasets/arabic/` | Source data used during training |
| `data/` | Combined raw and preprocessed CSV files generated by training |

Each language folder under `saved_models/` must contain **all six** of these files:

| File | Contents |
| --- | --- |
| `tfidf.pkl` | Fitted TF-IDF vectorizer |
| `svm.pkl` | Linear SVM classifier |
| `nb.pkl` | Multinomial Naive Bayes classifier |
| `tokenizer.pkl` | Fitted neural-network tokenizer |
| `meta.pkl` | Language and sequence-length metadata |
| `lstm.keras` | Saved bidirectional LSTM model |

The loader opens the complete pipeline before selecting a classifier. TensorFlow/Keras and all six files are therefore required even when using SVM or Naive Bayes. Inference does not read the training datasets.

If you received a source/update archive, merge it into the existing project folder while retaining its `saved_models/`, `datasets/`, and `data/` directories. The source package by itself does not contain the trained artifacts or datasets. Virtual environments are recreated locally rather than transferred between computers.

## Verify the setup

The basic check inspects the expected dependencies, NLTK resources, and all three model folders:

```powershell
.\.venv\Scripts\python.exe verify_setup.py
```

For an actual loading and prediction check:

```powershell
.\.venv\Scripts\python.exe verify_setup.py --smoke
```

The smoke check exercises the three classifiers for each of the three language settings using sample comments. It does not retrain or score model accuracy. A successful file or package check alone does not prove that serialized models load successfully. Source inspection and Python compilation are also distinct from running inference with the original model files.

Keep the recorded dependency versions when checking existing artifacts. Scikit-learn does not support loading persisted models across arbitrary version changes; see its [model persistence documentation](https://scikit-learn.org/stable/model_persistence.html#security-maintainability-limitations). The saved metadata does not record the original training package versions, so the captured environment is a starting point rather than proof of artifact compatibility.

## Train again

Training is optional when using the supplied models. To prepare for it:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-training.txt
.\.venv\Scripts\python.exe verify_setup.py --training
.\.venv\Scripts\python.exe main.py
```

Choose **`1`**, then the language setting. This runs collection, preprocessing, training, evaluation, and saving. It rebuilds the raw/cleaned files and replaces the selected language's saved pipeline when training completes. Preserve a separate copy of existing artifacts if you need to compare them with a new run.

English collection downloads a Parquet file from [Deysi/spam-detection-dataset](https://huggingface.co/datasets/Deysi/spam-detection-dataset), so English and multilingual training require internet access and that source to remain available. `pyarrow==22.0.0` and `huggingface-hub==0.36.0` are additional collection dependencies; they were not present in the captured environment and have not been validated in a complete training run.

Arabic collection writes CSV conversions alongside its source files. The generated files `data/cleaned_data_en` and `data/cleaned_data_ar` contain CSV data despite having no extension.

## Pipeline notes

Preprocessing normalizes text, replaces URLs/mentions/hashtags/emojis with tokens, handles punctuation and repeated letters, and removes selected stopwords. English processing also expands contractions and slang. The multilingual prediction path uses Arabic preprocessing when language detection identifies Arabic and otherwise falls back to English.

Training uses stratified **80%/10%/10%** train/validation/test splits. TF-IDF uses unigrams and bigrams with up to 30,000 features; both TF-IDF and the neural tokenizer are fitted on the training split. The neural architecture uses an embedding, bidirectional LSTM, dropout, and dense layers, with early stopping. NumPy and several scikit-learn operations use seed `42`; full training determinism is not established.

The preparation changes concern paths, setup, and loading diagnostics. Existing preprocessing order, label mapping, and model architecture are retained to preserve the inputs expected by the saved artifacts. No historical accuracy results are asserted here.
